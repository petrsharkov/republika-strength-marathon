# Автоматическое развёртывание на VPS

Поддерживается Linux VPS x86_64 с Docker, Bash и flock. Обычный тариф хостинга без SSH/Docker не подходит. Запуск по push в main/master или вручную: Actions → Deploy to VPS → Run workflow. До заполнения Secrets развёртывание пропускается.

## Secrets

В GitHub: Settings → Secrets and variables → Actions → New repository secret. Можно использовать environment production вместо repository secrets.

| Имя | Значение |
| --- | --- |
| DEPLOY_HOST | IP или доменное имя VPS, без https:// |
| DEPLOY_USER | SSH-пользователь с правами запускать Docker |
| DEPLOY_SSH_KEY | Полный приватный SSH-ключ для этого пользователя |
| DEPLOY_KNOWN_HOSTS | Проверенная запись host key сервера из known_hosts |
| DEPLOY_PORT | Необязательно, по умолчанию 22 |

Приватный ключ не отправляйте в чат и не коммитьте. Публичную часть ключа добавьте в ~/.ssh/authorized_keys на сервере. Пользователь должен иметь доступ к Docker и свободное место для образов и резервных копий. DEPLOY_KNOWN_HOSTS получите через ssh-keyscan -H SERVER (для другого порта: -p PORT), затем сравните отпечаток с ключом, показанным в доверенной консоли провайдера. Автоматическое принятие неизвестного ключа отключено.

## Первое развёртывание

1. Загрузите все файлы проекта, включая скрытую папку .github, в репозиторий.
2. На VPS установите Docker и Nginx, настройте SSH-пользователя и ключ.
3. Заполните Secrets. Если задана защита environment production, подтвердите запуск в GitHub.
4. Запустите workflow. Контейнер слушает только 127.0.0.1:3000.
5. Направьте DNS домена на VPS. Используйте deploy/nginx.conf, заменив домен, и подключите HTTPS через Certbot.

## Данные и обновления

Режим VPS использует Node.js 24 и SQLite, без Cloudflare для обработки запросов. Docker volume republika-marathon-data хранит /data/marathon.sqlite; пересоздание контейнера его не удаляет. SQL-миграции выполняются один раз, атомарно. Перед обновлением создаётся онлайн-копия базы в /data/backups. Не удаляйте этот volume.

Существующие записи с опубликованного Site автоматически не переносятся: новая база изначально пустая. Перенос текущих участников и результатов нужно выполнить отдельно перед переключением домена.

Сначала новая версия запускается без публичного порта и проверяет API результатов вместе с базой. Затем переключается основной контейнер. При ошибке запуска предыдущий контейнер возвращается. Переключение вызывает краткую паузу. Откат контейнера не откатывает схему базы: для несовместимых миграций нужна ручная проверка и восстановление резервной копии. Копии базы и старые Docker-образы пока сохраняются без автоматического удаления; контролируйте диск и настройте внешнее резервное копирование.

Команды на сервере:

```bash
docker ps
docker logs --tail 100 republika-marathon
docker volume inspect republika-marathon-data
```

## Границы проверки

Код режима VPS можно собрать и проверить локально до выдачи доступа к серверу. SSH, Docker на целевом VPS, DNS и HTTPS проверяются после настройки Secrets. Без подключения GitHub подготовленные файлы нужно загрузить в репозиторий вручную.
